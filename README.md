# Metacritic Games Service

Тестовое задание, AI Automation Engineer.

**Демо:** [ai-engineer-task-production.up.railway.app](https://ai-engineer-task-production.up.railway.app/games)

## Что это

Сервис раз в час забирает новые игры с Metacritic, складывает их в Postgres и
показывает каталог: карточка с оценками по всем платформам, резюме отзывов
критиков и игроков от LLM, похожие игры, заключение по летсплею с YouTube.
Плюс страница мониторинга, на которой видно идущий обход.

Данные берутся из открытого JSON API `backend.metacritic.com`, HTML не
разбирается (почему — ниже, в «Как делался проект»).

## Что реализовано

| Часть ТЗ | Состояние |
|---|---|
| Часовой обход каталога | есть: New Releases, дальше SEE ALL по курсору дня, 20 игр за заход, повторов внутри суток нет |
| Список игр: поиск, фильтр по платформе, сортировка, пагинация | есть, всё через htmx-фрагмент без перезагрузки страницы |
| Карточка: описание, разработчик, издатель, ESRB, жанры, обложка, трейлер, Metascore и Userscore по каждой платформе | есть |
| Резюме отзывов критиков и игроков (LLM) | есть, два раздельных блока в карточке |
| Похожие игры | есть, top-5 из своей базы по пересечению жанров и совпадению разработчика |
| Доп. 2: мониторинг и кнопка запуска | есть: `/status` с живой лентой через SSE и ручным заходом |
| Доп. 1: летсплеи | есть: самый просматриваемый ролик ищется через `yt-dlp`, пересказ берётся у 300.ya.ru, заключение по нему делает модель; в карточке блок со ссылкой на ролик. Часть роликов сервис пересказать не берётся — такие игры остаются без блока |

Из плана не сделан T-49: ручной запуск не переклеймивает игры, упавшие
сегодня, — они переобработаются на следующие сутки.

## Архитектура

| Модуль | Что внутри |
|---|---|
| `app/clients/` | HTTP-клиент Metacritic: один `AsyncClient`, глобальный лимит 1 rps, retry с backoff, маппинг ответов в DTO |
| `app/ingest/` | заход: курсор дня, claim игр, выбор батча, upsert, оркестратор с advisory-локой |
| `app/llm/` | адаптер Gemini, загрузка промптов, JSONL-лог вызовов, пайплайн резюме отзывов |
| `app/letsplay/` | поиск ролика через yt-dlp, пересказ через 300.ya.ru, пайплайн летсплея |
| `app/web/` | страницы, htmx-фрагменты, SSE |
| `app/events.py`, `app/state.py` | шина событий обхода и состояние воркера, из которого рисуется `/status` |
| `schema.sql` | вся схема одним файлом, применяется при старте приложения; миграций нет |

Один заход: advisory-лока → батч игр → на каждую игру `product` плюс
Userscore по её платформам → upsert в транзакции → best-effort обогащение
(резюме отзывов, летсплей) → строка в `runs`. Падение одной игры не роняет
заход, а отказ LLM или летсплея не меняет статус самой игры: каталожная часть
уже в базе, обогащение дозаполнится следующим заходом.

Подробности и обоснование решений — в [`docs/10-design.md`](docs/10-design.md).

## Запуск

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/) и Postgres 14+
(расширение `pg_trgm` ставится само вместе со схемой).

```bash
cp .env.example .env     # заполнить DATABASE_URL, ADMIN_TOKEN, GOOGLE_API_KEY, YA300_SESSION_ID
uv sync
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Схема накатывается при старте, отдельной команды миграции нет. Готовность —
`GET /healthz`, он же проверяет соединение с базой. Первого планового захода
можно не ждать:

```bash
curl -X POST localhost:8000/admin/run -H "X-Admin-Token: $ADMIN_TOKEN"
```

В контейнере:

```bash
docker build -t metacritic-digest .
docker run --env-file .env -p 8000:8000 metacritic-digest
```

### Переменные окружения

| Переменная | Обязательна | Зачем |
|---|---|---|
| `DATABASE_URL` | да | Postgres. Форма `postgresql://…` приводится к asyncpg сама |
| `ADMIN_TOKEN` | да | заголовок `X-Admin-Token` для `POST /admin/run` и кнопка на `/status` |
| `GOOGLE_API_KEY` | для резюме | ключ Google AI Studio; без него резюме и заключения получают статус `llm_failed` |
| `YA300_SESSION_ID` | для летсплеев | сессионная кука 300.ya.ru; без неё летсплеи получают `service_error` с причиной `no_session` |
| `SCHEDULER_ENABLED` | нет (`true`) | часовой планировщик; выключается на время локальных прогонов |
| `LLM_ENABLED` | нет (`true`) | общий рубильник обращений к модели |
| `GEMINI_MODEL` | нет (`gemini-3.5-flash-lite`) | имя модели; от него не зависит ничего, кроме самого вызова |
| `LETSPLAY_ENABLED` | нет (`true`) | выключает поиск и пересказ летсплеев целиком |

Остальные (`METACRITIC_*`, `GEMINI_*`, `LETSPLAY_*` — троттлинг, таймауты,
лимиты) перечислены в [`.env.example`](.env.example) и
[`app/config.py`](app/config.py) со значениями по умолчанию.

## Интерфейс

| Маршрут | Что делает |
|---|---|
| `GET /` | редирект на `/games` |
| `GET /games` | список; query: `q`, `platform`, `sort=metascore\|userscore\|new`, `page` |
| `GET /games/fragment` | тот же список без layout — цель htmx-подмены |
| `GET /game/{slug}` | карточка: платформы и оценки, трейлер, резюме, похожие игры, летсплей |
| `GET /status` | мониторинг: счётчики за сутки, текущая игра, лента событий, кнопка запуска |
| `GET /events` | `text/event-stream` — панель и лента готовым HTML, keep-alive раз в 15 с |
| `POST /admin/run` | ручной заход; 202 — принят, 409 — обход уже идёт, 401 — нет токена |
| `GET /healthz` | 200 при живой базе |

## Работа с LLM

Промпты вынесены в [`prompts/`](prompts/) с версией в имени файла, в коде
только загрузка. Ответ забирается структурой, а не парсингом текста.

Отзывы пользователей — недоверенный ввод: цитаты идут отдельным сообщением
в `<review>`, системная часть промпта предписывает игнорировать инструкции
внутри.

Каждый вызов пишется в `logs/llm/YYYY-MM-DD.jsonl`, отдельная строка на
каждую попытку.

LLM-слой изолирован за интерфейсом `LlmClient`. Смена провайдера — один
адаптер; ретраи, circuit breaker и логирование провайдеро-независимы.

## Ограничения

- Пересказ летсплеев держится на 300.ya.ru — неофициальном сервисе без
  публичной документации, с сессионной кукой вместо ключа. Контракт снят с
  живого API 07.09.2026 и описан в docstring `app/letsplay/retelling.py`;
  сменить его могут без предупреждения, а кука рано или поздно протухнет —
  тогда игры получат `service_error` с причиной `auth`. Часть роликов сервис
  не осиливает и сам (отвечает `status_code=2`) — такая игра остаётся без
  блока в карточке. Всё это штатная деградация: карточка без летсплея —
  нормальное состояние (ADR-8), остальная обработка не страдает.
- Поиск ролика (`yt-dlp ytsearch`) локально работает, но с датацентрового IP
  YouTube может отвечать `LOGINREQUIRED` (ADR-8) — тогда игры на проде получат
  `not_found`. Это видно на `/status` и в таблице `letsplays`.
- Бесплатный тир Google AI Studio считает квоту отдельно по каждой модели и
  выдаёт её небольшими суточными лимитами. При исчерпании резюме получает
  статус `llm_failed`, следующий заход пробует снова.
- Persistent volume на Railway не покупали (OQ-3): `logs/llm/*.jsonl` на проде
  живут до редеплоя, полные raw-логи вызовов собираются с локального прогона.
- Один инстанс приложения. Advisory-лока не даёт заходам наложиться, но
  планировщик, курсор дня и claim рассчитаны именно на один процесс.
- Публичные страницы открыты всем, токеном закрыт только `POST /admin/run`.
- Обложки отдаёт CDN Metacritic по `bucketPath`, локально ничего не хранится:
  если картинка уедет у них, она пропадёт и здесь.

## Тесты

```bash
uv run pytest
```

Тестам нужен живой Postgres из `DATABASE_URL`: там, где проверяются `ON
CONFLICT`, advisory-лока и статусы, база настоящая, а внешние сервисы
подменены. Без базы такие тесты помечаются `skipped`, остальные проходят.

Railway, `Dockerfile` + `railway.json`. Один инстанс: планировщик, курсор дня и claim рассчитаны на один процесс.
