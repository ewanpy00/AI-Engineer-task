# T-02 — Подключение к Postgres + bootstrap schema.sql

Срез: S0. Обязательная часть: да.

## Цель

Дать приложению асинхронное подключение к Postgres и механизм применения
`schema.sql` при старте (идемпотентно, `CREATE TABLE IF NOT EXISTS`), как
зафиксировано в ADR-3 и `11-decisions.md` («накатываем схему напрямую»).

## Файлы

- `app/db.py` — SQLAlchemy async engine (asyncpg), фабрика сессий/соединений
- `schema.sql` (корень репозитория) — пока только `CREATE EXTENSION IF NOT
  EXISTS pg_trgm;`, наполняется таблицами в последующих задачах (T-04, T-17,
  T-21, T-28, T-40)
- `app/web/routes_health.py` — `GET /healthz`, проверяет БД (`SELECT 1`)

## Зависимости

T-01.

## Определение готовности

- При старте приложения `schema.sql` применяется автоматически (повторный
  запуск ничего не ломает — идемпотентность проверена локальным перезапуском).
- `GET /healthz` возвращает 200 при живой БД и не 200 при недоступной
  (например, неверный `DATABASE_URL`).
- Доступ к БД идёт через SQLAlchemy (async), а не напрямую через `asyncpg`
  без обёртки — по стеку из `11-decisions.md`.
