# T-37 — Публикация событий из ingest runner

Срез: S6. Обязательная часть: нет (доп. часть 2).

## Цель

Заставить `IngestRunner` публиковать события в `EventBus` (T-35) и обновлять
`WorkerState` (T-36) на каждом шаге захода.

## Файлы

- `app/ingest/runner.py` — публикация событий `run_started`, `game_started`,
  `game_done`, `game_failed`, `llm_call`, `run_finished`, `counters` (виды —
  по design §4.3) в соответствующих точках `run`/`process_game`; обновление
  полей `WorkerState` синхронно с публикацией

## Зависимости

T-35, T-36, T-22.

## Определение готовности

- Один ручной заход на 3-5 играх публикует ожидаемую последовательность
  событий: `run_started` → (`game_started`/`game_done`|`game_failed`)×N →
  `run_finished`.
- `WorkerState.current_game` в момент обработки конкретной игры совпадает с
  её названием/slug.
- Подписчик, подключившийся в середине захода (T-38 будет его использовать),
  получает через `recent()` события, случившиеся до подключения, и через
  `subscribe()` — все последующие.
