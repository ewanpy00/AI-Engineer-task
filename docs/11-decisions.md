# Решения по проекту

При конфликте с 10-design.md главным считается этот файл

## Откуда берём данные

Только JSON API на backend.metacritic.com. Подробности в 00-research.md

## Стек

Python 3.12, FastAPI, PostgreSQL, SQLAlchemy
Планировщик — APScheduler внутри того же процесса
Интерфейс — серверный рендеринг на Jinja2 плюс HTMX. без SPA

## Как обходим каталог

Раз в час. День считаем по UTC

Первый заход дня берёт двадцать игр из блока New Releases.
Все следующие заходы идут по разделу SEE ALL, сдвигая offset на
двадцать за раз

Обязательно фильтруем то, что уже обрабатывали сегодня: New Releases
входит в SEE ALL, поэтому пересечения гарантированы. Если после
фильтрации набралось меньше двадцати игр, то берём следующие страницы,
но не больше пяти за один заход

Дедуп только по id игры

Состояние храним в двух таблицах: текущая фаза и offset на день,
и журнал обработанных игр по дням

## Резюме отзывов

На вход модели идут готовые подборки цитат с summary-эндпоинтов,
уже разложенные по тональности. Если подборка пустая — fallback
на полный список отзывов

Отзывы берём только для ведущей платформы. Пользовательский рейтинг —
для всех платформ игры

Модель - Claude Haiku через Anthropic API. Ответ забираем структурой
через tool use, а не просим вернуть JSON текстом: так не нужно
парсить и чинить формат

Текст промптов лежит в prompts/ с номером версии, в коде только
загрузка файла. Каждый вызов пишем в logs/llm/ построчным JSON:
время, версия промпта, модель, запрос, ответ, токены, задержка.

## Похожие игры

Считаем по пересечению жанров, с надбавкой за совпадение
разработчика. Берём топ-5. Считаем в момент открытия карточки
обычным SQL-запросом, не кэшируем

## Мониторинг и ручной запуск

Страница со статусом получает обновления через SSE. Состояние
воркера держим в памяти приложения, счётчики после рестарта
восстанавливаем из журнала обработанных игр

Кнопка запуска дёргает ту же функцию, что и планировщик, в фоне
Параллельный запуск блокируем флагом

## Схема базы

Пока разрабатываем — накатываем схему напрямую за день она поменяется несколько раз

## Хранение файлов

Обложки не скачиваем. В базе лежит путь картинки, отдаёт её CDN Metacritic

Всё что должно пережить рестарт лежит в Postgres.

## Дополнительная часть 1: летсплеи

Делаем через 300.ya.ru. Проверено вручную: сервис принимает ссылку
на ролик и возвращает пересказ, авторизация идёт через session_id.

Почему не напрямую с YouTube: официальный API транскрипт чужого
видео не отдаёт в принципе (нужен OAuth владельца канала),
а неофициальные пути блокируются на IP дата-центров, то есть
именно там, где будет жить сервис. Подробности в 00-research.md §5.

Поиск самого ролика через yt-dlp

session_id держим в переменной окружения, в репозиторий не кладём.
Это сессионная кука, она истекает поэтому фича проектируется
как необязательная: если пересказ не получен, карточка игры
показывается без него, обработка не падает и не ретраится
бесконечно. В базе для летсплея отдельный статус: получен,
не найден, ошибка сервиса

В карточке показываем пересказ и ссылку на исходный ролик
